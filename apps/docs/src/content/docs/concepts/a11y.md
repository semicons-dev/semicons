Accessible icons benefit everyone. This page covers how Semicons handles accessibility by default and best practices for different use cases.

## Overview

This page covers:
- Decorative vs meaningful icons
- Default accessibility behavior in runtime components
- ARIA attributes and screen reader support
- Button icon patterns

## Icon Accessibility Basics

### Decorative Icons

Decorative icons add visual context but don't convey information on their own. They're hidden from screen readers.

**Examples**:
- Menu icon next to "Menu" text
- Search icon in a search input
- Status icon in a notification badge

### Meaningful Icons

Meaningful icons convey information that users need to understand. They must be announced by screen readers.

**Examples**:
- Error icon indicating a form error
- Warning icon in an alert
- Status indicator showing connection state

## Default Behavior

### React Runtime

```tsx
import { Icon } from '@semicons/react'

// Decorative (default)
<Icon name="navigation:menu" />
// Renders: <svg aria-hidden="true" ...>

// Meaningful
<Icon name="status:error" decorative={false} ariaLabel="Form has errors" />
// Renders: <svg role="img" aria-label="Form has errors" ...>
```

### Vue Runtime

```vue
<Icon name="navigation:menu" />
<!-- Decorative: aria-hidden="true" -->

<Icon 
  name="status:error" 
  :decorative="false"
  aria-label="Form has errors"
/>
<!-- Meaningful: role="img" aria-label="Form has errors" -->
```

## Props Reference

### decorative

| Value | Behavior | Output |
|-------|----------|--------|
| `true` (default) | Hidden from screen readers | `aria-hidden="true"` |
| `false` | Announced by screen readers | `role="img"` + `aria-label` |

### ariaLabel

Required when `decorative={false}`.

```tsx
<Icon 
  name="status:error"
  decorative={false}
  ariaLabel="Error: Form validation failed"
/>
```

### title

Adds a `<title>` element for hover tooltips:

```tsx
<Icon name="navigation:menu" title="Open menu" />
```

## Common Patterns

### Icon with Text

The icon should be decorative since text provides the label:

```tsx
<button aria-label="Open menu">
  <Icon name="navigation:menu" />
  <span>Menu</span>
</button>
```

### Icon Only Button

The icon is the only label - must be meaningful:

```tsx
<button aria-label="Open menu">
  <Icon name="navigation:menu" decorative={false} />
</button>
```

### Status Indicator

Conveys information - must be meaningful:

```tsx
<div role="status">
  <Icon 
    name="status:error" 
    decorative={false}
    ariaLabel="Error: Submission failed"
  />
  <span>Submission failed</span>
</div>
```

### Alert with Icon

Icon reinforces the message:

```jsx
<div role="alert">
  <Icon 
    name="alert:warning" 
    decorative={false}
    ariaLabel="Warning"
  />
  <p>Please review before submitting</p>
</div>
```

## Accessibility Checklist

- [ ] Decorative icons have `decorative={true}` (default)
- [ ] Meaningful icons have `decorative={false}` and `ariaLabel`
- [ ] Icon-only buttons have `aria-label` on the button
- [ ] Status icons are announced
- [ ] Error/warning icons reinforce the message

## When to Use

- All icons in user-facing applications
- Icons in buttons, forms, alerts
- Status indicators

## When Not to Use

- Icons in purely decorative headers
- Animated loaders (use `role="progressbar"` instead)

## Common Issues

### Missing ariaLabel

```bash
Warning: Icon with decorative={false} requires ariaLabel
```

**Solution**: Add the `ariaLabel` prop.

### Redundant announcement

**Problem**: Both icon and text are announced.

**Solution**: Make icon decorative when text is present.

### Icon-only button not labeled

```tsx
// Bad
<button><Icon name="search" /></button>

// Good
<button aria-label="Search">
  <Icon name="search" />
</button>
```
